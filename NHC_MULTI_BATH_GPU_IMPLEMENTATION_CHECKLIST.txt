GPU-Only Multi-Temperature NHC Implementation Checklist
Date: 2026-04-23
Status: Implementation contract (pre-coding)

==============================================================================
0) Goal and Non-Negotiable Constraints
==============================================================================

Implement two-/multi-temperature Nose-Hoover Chain (NHC) thermostatting where
disjoint particle subsets are coupled to different target temperatures, while
keeping the simulation loop GPU-only.

Hard constraints:
1. No CPU fallback in per-step integration logic.
2. One particle belongs to exactly one NHC bath at runtime.
3. Multi-bath support must remain integrator-agnostic at orchestration level.
4. Existing single-bath NHC behavior must remain valid and backward compatible.
5. Freeze masks must be respected in NHC DOF accounting.

2) Data Model Refactor (Simulation.jl)
==============================================================================

2.1 NHCParams: move from scalar-bath to multi-bath capable parameters.

Current (single-bath):
- mass::T
- target_temperature::T
- tau::T
- substeps::Int
- chain_masses::Vector{T}

Target (multi-bath capable):
- mass::T
- substeps::Int
- chain_length::Int
- nbaths::Int
- target_temperature::Vector{T}      # length nbaths
- tau::Vector{T}                     # length nbaths
- chain_masses::Matrix{T}            # size (chain_length, nbaths)

Compatibility rule:
- Existing constructor with scalar temperature/tau creates nbaths=1.

2.2 NHCWorkspace: add per-bath and bath-mapping GPU buffers.

Required fields:
- particle_bath_id::CuArray{Int32,1}       # length N, values in 1:nbaths
- bath_counts::CuArray{Int32,1}            # length nbaths
- dof_per_bath::CuArray{T,1}               # length nbaths
- kinetic_total_per_bath::CuArray{T,1}     # length nbaths
- thermostat_kinetic_per_bath::CuArray{T,1}
- thermostat_potential_per_bath::CuArray{T,1}
- last_velocity_scale_per_bath::CuArray{T,1}
- xi::CuArray{T,2}                         # size (chain_length, nbaths)
- eta::CuArray{T,2}                        # size (chain_length, nbaths)
- chain_force::CuArray{T,2}                # size (chain_length, nbaths)
- chain_masses::CuArray{T,2}               # size (chain_length, nbaths)
- dof_dirty::Bool                          # true when bath mapping/freeze changes
- kinetic_initialized::Bool

Note:
- Keep all per-step thermostat state on device.
- Host-side signatures are acceptable only for workspace resize/rebuild checks.

2.3 NHCSpec remains:
- params::NHCParams{T}
- workspace::NHCWorkspace{T}

No changes needed in integrator protocol type hierarchy.

3) Public API Shape (Constructors and Controls)
==============================================================================

3.1 Constructor behavior

Keep:
- nosehooverchain(st; temperature, tau, chain_length, substeps, mass, chain_masses)

Add:
- nosehooverchain(st; temperatures::AbstractVector, taus::AbstractVector,
                  chain_length, substeps, mass, chain_masses=nothing)

Rules:
1. length(temperatures) == length(taus) == nbaths
2. chain_masses (if provided) must match (chain_length, nbaths) or be reshaped
3. all temperatures > 0, taus > 0, chain masses > 0

3.2 Bath assignment API (Filters-based)

Add in Filters.jl:
1. assign_nhc_baths!(spec::NHCSpec, st::SimulationState,
                     pairs::Pair{<:Filter,<:Integer}...)
2. set_thermostat_temperature!(spec::NHCSpec, st::SimulationState,
                               value::Real; filter::Filter=All())
3. set_thermostat_temperature!(spec::NHCSpec, st::SimulationState,
                               pairs::Pair{<:Filter,<:Real}...)
4. set_thermostat_timescale!(spec::NHCSpec, st::SimulationState,
                             value::Real; filter::Filter=All(),
                             rescale_chain_masses::Bool=true)
5. set_thermostat_timescale!(spec::NHCSpec, st::SimulationState,
                             pairs::Pair{<:Filter,<:Real}...;
                             rescale_chain_masses::Bool=true)

Alias:
- set_temperature!(spec::NHCSpec, st, dt, ...) routes to
  set_thermostat_temperature! for NHC.

Behavior rule:
- Remove the current "NHC temperature control is global" error path.
- For NHC, filter mapping updates bath parameters and per-particle bath IDs.

4) GPU Kernel Work Items (Simulation.jl)
==============================================================================

4.1 Bath mapping and DOF preparation kernels

Implement:
1. _nhc_assign_bath_id_kernel!(particle_bath_id, idx, bath_id)
2. _nhc_count_baths_kernel!(bath_counts, particle_bath_id)
3. _nhc_compute_dof_kernel!(dof_per_bath, particle_bath_id, freeze_mask, D)

Notes:
- D = 2 or 3 dimensions.
- freeze_mask != 0 should be excluded from thermostatted DOF.

4.2 Kinetic reduction by bath

Implement:
1. _nhc_reduce_kinetic_by_bath_kernel!(kinetic_total_per_bath, Ekin, particle_bath_id)

Use atomic adds per bath.

4.3 Half-kick update by bath

Replace global kernels with bath-aware kernels:
1. _nhc_half_kick2_by_bath_kernel!
2. _nhc_half_kick3_by_bath_kernel!

Requirements:
- Update v and Ekin per particle.
- Atomically reduce Ekin into kinetic_total_per_bath[bath_id].

4.4 Thermostat scaling by bath

Replace global stage-scale kernels with:
1. _nhc_apply_stage_scale2_by_bath_kernel!
2. _nhc_apply_stage_scale3_by_bath_kernel!

Each particle uses scale = last_velocity_scale_per_bath[bath_id].

4.5 NHC chain stage propagation by bath

Replace single-bath chain kernel with bath-indexed kernel:
1. _nhc_chain_stage_multi_kernel!

Expected launch shape:
- threads >= nbaths, one thread handles one bath chain integration loop.

Per-bath inputs:
- dof_per_bath[b]
- target_temperature[b]
- kinetic_total_per_bath[b]
- chain_masses[:, b]
- xi[:, b], eta[:, b], chain_force[:, b]

Per-bath outputs:
- updated kinetic_total_per_bath[b]
- last_velocity_scale_per_bath[b]
- thermostat_kinetic_per_bath[b]
- thermostat_potential_per_bath[b]

5) Stage Orchestration Integration (Simulation.jl)

1. _ensure_nhc_kinetic_initialized! -> initialize per-bath totals
2. _nhc_apply_half_kick! -> call by-bath kernels
3. _run_nhc_chain_stage! -> call multi-bath chain kernel
4. _nhc_apply_stage_scale! -> by-bath scaling

Workspace lifecycle:
1. ensure_integrator_workspace!(::NHCSpec, st) must validate/resize all
   (chain_length, nbaths, N)-dependent buffers.
2. Set workspace.dof_dirty=true when:
   - bath assignment changes
   - freeze configuration changes
   - N changes

9) Performance Acceptance Criteria
==============================================================================

Baseline:
- current single-bath NHC benchmark suite performance.

Target:
1. Single-bath mode after refactor: <= 5% slowdown vs baseline.
2. Two-bath mode: maintain stable throughput; avoid serial host loops in step.
3. GPU utilization should improve over previous CPU-assisted grouped attempts.

Profiling checklist:
1. Kernel launch counts per step
2. Time share in:
   - force kernels
   - half-kick by-bath kernels
   - chain stage kernel
   - scaling kernel
3. Check for hidden sync points (avoid unnecessary CUDA.@sync)

==============================================================================
11) Explicit Risks to Watch
==============================================================================

1. Bath overlap or uncovered particles from filter mappings.
2. Incorrect DOF counting under freeze/unfreeze transitions.
3. Chain mass rescaling applied globally instead of targeted baths.
4. Hidden host synchronization reducing utilization.
5. Writer regressions from changed observable schema.

==============================================================================
12) Definition of Done
==============================================================================

Done means all conditions below are true:
1. Single-bath NHC remains functional and benchmark suite remains acceptable.
2. Two-/multi-bath NHC runs with filter-assigned subsets without errors.
3. NHC integration hot path is GPU-only.
4. Tests for API, dynamics, and observables pass.
5. Chari-style two-temperature example runs end-to-end and logs expected group
   temperatures plus trajectory output.
