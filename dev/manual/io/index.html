Trajectories and tables

Attach writers to a Simulation to save measurements and configurations on independent schedules.

Save a table and a trajectory

all = Group(:all, AllSelection())
thermo = ThermodynamicObservable(all; name=:thermo)
writers = [
    TableWriter("thermo.csv"; every=100,
        observables=[thermo => [:temperature, :total_energy]], mode=:replace),
    GSDWriter("trajectory.gsd"; every=1_000, group=all,
        write_start=true, mode=:replace),
]
sim = Simulation(system; groups=Groups(all), integrator=integrator,
                 observables=[thermo], writers=writers)
run!(sim, 10_000)

A table is convenient for plotting time series. GSD stores particle configurations and metadata for visualization and continuing a simulation.

Choose when to write

Use every=100 for a regular interval, or pass an explicit schedule:

TableWriter("selected.csv";
    schedule=AtSteps([0, 100, 1_000]),
    observables=[thermo => [:temperature]],
)
GSDWriter("production.gsd"; schedule=Between(1_000, 10_000; every=500))

In-memory workflow output

InMemoryWriter is a workflow writer like TableWriter and GSDWriter, but it keeps frames in host memory, for analysis or debugging in the same Julia session without file I/O:

mem = InMemoryWriter(every=100, fields=[:positions, :forces, :energy, :virial])
sim = Simulation(system; integrator=integrator, writers=[mem])
run!(sim, 10_000)
data = recorded_data(mem)
data.step                  # step of each frame
data.positions[:, :, end]  # N × D, rows in particle-id order
data.potential_energy      # one value per frame
empty!(mem)                # drop the recorded frames

Each recorded frame copies the requested fields from the device, so record only what you need at the interval you need.

ParticleDynamics.Workflow.InMemoryWriter — Type
InMemoryWriter(; every=nothing, schedule=nothing, fields=[:positions], write_start=false)

Scheduled writer that keeps frames in host memory instead of a file, for analysis and debugging inside the same Julia session. fields selects any of :positions, :unwrapped_positions, :velocities, :forces, :energy, :virial:

  • per-particle data (:positions, :unwrapped_positions, :velocities, :forces) is stored in particle-id order, i.e. the order of the ParticleSystem, independent of the engine's spatial sorting;
  • :energy stores the total kinetic and potential energy;
  • :virial stores the total virial tensor.

Velocities are not recorded for Brownian dynamics (overdamped motion has none). Frames accumulate across stages and run! calls until empty!(writer); read them with recorded_data.

ParticleDynamics.Workflow.recorded_data — Function
recorded_data(writer::InMemoryWriter) -> NamedTuple

Frames recorded so far. step holds the step of each frame. Per-particle fields are N × D × nframes arrays (data.positions[:, :, k] is frame k, rows in particle-id order), energy gives kinetic_energy and potential_energy vectors, and virial is a D × D × nframes array. The arrays are copies; the writer keeps recording.

File sessions

  • Workflow TableWriter and GSDWriter use mode=:replace to replace a file once when their simulation writer session first opens it. Later stages append to that session, even though handles are closed at stage boundaries. Calling prepare! again with the same writer preserves the session. A new Simulation starts a new session; use mode=:append to retain an existing file across separate simulations.
  • GSD writing stays outside the simulation hot path and is the preferred trajectory format for richer restart data.
