Bonds, minimization and pressure

All quantities are plain numbers in caller-chosen consistent units (length L, energy E, time). Angles are radians.

Typed bonded interactions

Topology sections carry optional labels; each force descriptor applies to the tuples whose label equals its type (:default when a section has no labels). Atom order is kept: the middle atom of an angle is the vertex, and torsions use the IUPAC signed dihedral φ = atan2(|b2| b1·(b2×b3), (b1×b2)·(b2×b3)) of the ordered quartet.

topology = Topology(bonds=bonds, bond_types=[:backbone, :side, …],
                    angles=angles, dihedrals=dihedrals, impropers=impropers)
forces = Force[
    WCA(epsilon=1.0, sigma=1.0),
    HarmonicBondForce(k=300.0, r0=1.0, type=:backbone),
    FENEBondForce(k=30.0, R0=1.5, type=:side),
    HarmonicAngleForce(k=30.0, theta0=deg2rad(115)),
    PeriodicDihedralForce(k=[1.0, 0.4], n=[1, 3], phase=[0.0, 0.0]),
    HarmonicImproperForce(k=10.0, chi0=0.0),
]

Every label must be assigned exactly once per section; missing or duplicate assignments are errors. Torsions and impropers require 3D. Invalid geometry (zero-length bonds, collinear torsion planes, FENE beyond R0) raises DomainError with the topology index. Exclusion and 1–4 scaling policies beyond the existing bonded-pair exclusion are not implemented yet.

ParticleDynamics.Workflow.HarmonicAngleForce — Type
HarmonicAngleForce(; k, theta0, type=:default)

U = k(θ-θ0)²/2 on topology.angles (vertex = middle atom). θ0 = π (linear equilibrium) is handled exactly at collinear geometry; any other θ0 reports collinear geometry as a domain error.

ParticleDynamics.Workflow.CosineSquaredAngleForce — Type
CosineSquaredAngleForce(; k, theta0, type=:default)

U = k(cosθ - cosθ0)²/2 on topology.angles.

ParticleDynamics.Workflow.UreyBradleyAngleForce — Type
UreyBradleyAngleForce(; k_theta, theta0, k_r, r13, type=:default)

U = kθ(θ-θ0)²/2 + k_r(r13 - r13⁰)²/2 on topology.angles; the 1–3 distance term is part of this force and is not also counted as a bond.

ParticleDynamics.Workflow.PeriodicDihedralForce — Type
PeriodicDihedralForce(; k, n, phase, type=:default)

U = Σ_m k_m[1 + cos(n_m φ - δ_m)] on topology.dihedrals, with the IUPAC signed dihedral φ of the ordered quartet. k, n, phase are scalars or equal-length vectors (one Fourier term each); n_m are positive integers.

ParticleDynamics.Workflow.OPLSDihedralForce — Type
OPLSDihedralForce(; K1, K2, K3, K4=0, type=:default)

U = ½[K1(1+cosφ) + K2(1-cos2φ) + K3(1+cos3φ) + K4(1-cos4φ)] (LAMMPS opls convention), compiled into the Fourier evaluator.

ParticleDynamics.Workflow.RyckaertBellemansDihedralForce — Type
RyckaertBellemansDihedralForce(; C, type=:default)

U = Σ_{n=0}^{5} C_n cos(ψ)^n with ψ = φ - π (polymer convention: trans is ψ = 0). C holds six coefficients C0..C5.

ParticleDynamics.Workflow.HarmonicImproperForce — Type
HarmonicImproperForce(; k, chi0, type=:default)

U = k d²/2, d = wrap(χ - χ0) into (-π, π], where χ is the signed dihedral of the ordered improper quartet (torsion-style improper). Import adapters must map their central-atom convention onto this order.

Energy minimization

result = minimize!(sim; method=FIRE(dt_initial=1e-3, dt_max=1e-2),
                   force_tolerance=1e-4, max_displacement=0.05,
                   mobile=Group(:solvent, TypeSelection(:W)))

minimize! minimizes a Simulation using its declared forces; no thermostat runs. The box is fixed; non-mobile particles keep their interactions but do not move. FIRE (velocity-Verlet FIRE) uses forces only; SteepestDescent uses a backtracking Armijo line search on energies and therefore stops with :step_too_small once energy differences fall below rounding (in practice about |F| ≈ √(2 k eps E_term)). result.converged is true only when the largest mobile force reached force_tolerance.

FIRE requires dt_initial and dt_max; SteepestDescent requires initial_step. Control the run with force_tolerance, max_displacement, max_iterations and max_evaluations. The returned result includes converged, reason, iterations, initial_energy, final_energy and max_force; inspect the stopping reason before using the configuration.

Isotropic NPT

barostat = MonteCarloBarostat(pressure=2.0, kT=1.0, interval=25,
                              log_volume_step=0.01, seed=1, tune=true)
# or StochasticCellRescaling(pressure=2.0, kT=1.0, compressibility=0.1,
#                            tau=0.5, interval=10, seed=1)
integrator = Integrator(dt=4e-3, scheme=BAOAB(), forces=forces,
                        methods=[Langevin(all; gamma=1.0, kT=1.0)], barostat=barostat)

Pressure is in E/L³, compressibility in L³/E. Both barostats scale all coordinates with the cell and leave velocities unchanged. They currently require 3D, scheme=BAOAB() with one Langevin method on all particles at the barostat kT, no freezing or external potentials. Long-range electrostatics follow the cell: the mesh influence function, reciprocal virial and background term are recomputed at every cell change. Monte Carlo moves use a log-volume proposal with the (N+1) Jacobian; stochastic cell rescaling follows Bernetti & Bussi (2020) with a fresh virial at every event. barostat_diagnostics(sim) reports volume, acceptance and committed changes. GSD frames record log/barostat/state; continue a run with restore_barostat!(sim, read_gsd_log(path, "log/barostat/state")).

Monte Carlo moves sample the potential energy itself, so the Lennard-Jones cutoff convention matters (vdw_modifier, see Forces). Use :potential_shift to compare with GROMACS.

Size the neighbor-list capacity for the densest volume the run will visit: an overflow stops the run instead of truncating the list. Each barostat event currently triggers a neighbor rebuild, so events every 10–25 steps are a reasonable default.

Barostat API

ParticleDynamics.Workflow.Barostat — Type
Barostat

Abstract global pressure-control descriptor, passed as Integrator(...; barostat=...).

ParticleDynamics.Workflow.MonteCarloBarostat — Type
MonteCarloBarostat(; pressure, kT, interval=25, log_volume_step=0.01, seed, scale=:atoms, tune=false)

Isotropic Monte Carlo volume moves in log V with the (N+1) Jacobian, one attempt every interval steps. tune=true adapts log_volume_step toward 40% acceptance during the first 10 batches of 100 attempts and then freezes it. Same thermal requirements as StochasticCellRescaling.

ParticleDynamics.Workflow.StochasticCellRescaling — Type
StochasticCellRescaling(; pressure, kT, compressibility, tau, interval=10, seed, mode=:isotropic)

Isotropic stochastic cell rescaling (Bernetti & Bussi 2020) applied every interval steps over the elapsed MD time. Units: pressure E/L³, kT E, compressibility L³/E, tau time. Positions follow the cell; velocities are not scaled. Requires scheme=BAOAB() with one Langevin method on all particles at the same kT.

ParticleDynamics.Workflow.barostat_diagnostics — Function
barostat_diagnostics(sim) -> NamedTuple

Current volume and pressure-control counters. Monte Carlo: attempts, acceptance ratio, current log_volume_step, rejected invalid trials, and the committed volume change, potential-energy change and P·ΔV. C-rescale: events, committed volume change and the last barostat pressure.

ParticleDynamics.Workflow.barostat_state_record — Function
barostat_state_record(sim) -> Vector{Float64}

Restart record of the active barostat (written to GSD frames as log/barostat/state by GSDWriter): the pressure-control counters plus the time of the last event.

ParticleDynamics.Workflow.restore_barostat! — Function
restore_barostat!(sim, record) -> sim

Continue a barostat stream from a barostat_state_record, e.g. read_gsd_log(path, "log/barostat/state") of the restart frame. Call after prepare! with the same barostat descriptor (the seed is checked).
